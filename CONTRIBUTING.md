# Contributing

Bug reports and pull requests go to this repository, [Magikdidi24/tree-sitter-ruby](https://github.com/Magikdidi24/tree-sitter-ruby).
A parse bug is easiest to fix with the smallest Ruby snippet that shows it, the tree you get and what Ruby (or
[Prism](https://github.com/ruby/prism)) makes of it: `ruby -rprism -e 'pp Prism.parse(File.read(ARGV[0])).value' FILE`.

## Setup

```sh
npm ci
node_modules/.bin/tree-sitter generate   # after changing grammar.js
node_modules/.bin/tree-sitter test
```

Use the CLI from `node_modules`: `src/parser.c` must be generated by the version CI checks against (ABI 15).

## Before a pull request

- Add a test in `test/corpus` for the change, and in `test/highlight` for a query change.
- `cargo test` also checks that an incremental reparse gives the same tree as a fresh parse.
- `bundle exec ruby script/prism_diff.rb DIR` compares the trees with Prism on the Ruby files in `DIR`.
- `script/coverage.sh` prints how much of the scanner the tests run.
- The scanner must build without warnings: `cc -std=c11 -Wall -Wextra -Wpedantic -Wshadow -Werror -Isrc -c src/scanner.c`.
- CI also runs the bindings' tests on Linux, Windows and macOS, the sanitizers, a fuzzer, CodeQL, and `perf`, which
  fails when the parser runs more than 3 % more instructions than the base branch.

## Commits

A short subject, one or two lines on why, then what changes:

```
fix(scanner): a `;` on the line after `key:` follows a line break

Tree-sitter reuses the call and lexes the line break where no value may follow.

Before: `foo key:\n;` gives an extra empty statement after an edit
After:  the same tree as a fresh parse
```

Add a line under `## Unreleased` in CHANGELOG.md for anything a user of the grammar would notice.

## Releases

`script/release.sh X.Y.Z` bumps every manifest and lockfile, regenerates the parser and dates the changelog. Pushing
the tag `vX.Y.Z` publishes the packages to npm, crates.io and PyPI.
